# Design-Doc Loop (DDL)

## ✨ Intent

人間と LLM はセッション、エージェント、ハーネスをまたいで設計原則を共有し続けます。

DDL は硬直したプロセスではなく、作りたい設計の集まりです。

DDL のドキュメントは最終の成果物ではなく、設計がコードに反映されるまでの一時的なメモです。

> 詳しい背景理論、例、ガイドラインは [design_philosophy_extended.md](./design_philosophy_extended.md) を参照してください。
> すべてを読む必要はありません。必要なときに必要なものだけを参照してください。

-----

## 🎯 背景: セッションの断絶という問題

LLM との協働開発にはセッションの断絶という問題があります。

- 一つのエージェントが覚えていることは、次のセッション、エージェント、ハーネスからは見えません
- エージェントが覚えていることは、人間が合意したことではありません
- セッションが抱えるものが増えるほど、そのうちモデルが思い出せる割合は減るので、コンテキストは人間と同じくモデルにとっても予算です

そこで、コードの設計をメモとして LLM と共有します。

### ハーネス時代

Claude Code や Codex のようなエージェントのハーネスはいまでは指示ファイル、自動メモリ、長い会話の要約という自前の記憶を持っています。その記憶はエージェントの想起を助けますが、エージェントがそこに書いたものは人間が合意した記録ではありません。また、エージェントが作業を並列のサブエージェントに渡すと各サブエージェントはたいてい新しいセッションとして始まるので、断絶はワーカーが増えるたびに広がります。

希少な資源はもはやモデルの記憶ではなく、人間の注意と一つのセッションが抱えられるコンテキストです。共有するメモにはいまでは二つの働きがあります。一つはセッションをまたいで設計を保つことで、もう一つは人間が何を固定しどこを確認したいかをエージェントが走る前に伝えることです。

ハーネスはループの一部を担うこともできます。ハーネスが hook、エージェント定義、取り込みを備えているところでは、DDL のアダプタが人間の発言まで STOP を保ち、ワーカーをその役割にとどめ、メモをコンテキストに載せ続けます。規則そのものは変わらず、こうした仕組みのないセッションは規則を指示として実行します。

-----

## 💡 中核の原則

```
Human ←→ Document ←→ LLM
              ↓
            Code
```

ドキュメントが人間と LLM をつなぎ、コードはドキュメントに基づいて書かれます。

ただし、実装の途中で設計の問題が見つかることもあり、そのときはドキュメントを更新します。

最終的にはコードが正（source of truth）になります。DDL のドキュメントはコードや docs に統合され、不要になったら削除されます。形式にこだわる必要はありません。

-----

## 🔄 ループ

```
      Draft
        ↓
Design Document ⇄ Code
   (Realize ↓  ↑ Reflect)
```

### Draft

**Intent:** ユーザー側の体験を先に書く。

コードを実装する前に、そのコードがどう使われるかを書きます。API が使いやすいかを確かめてから実装します。

```python
# Draft: 実装の前に使い方を書く
async with Client("https://api.example.com") as c:
    users = await c.get("/users")  # この使い方で良いか？
```

体験から切り離せない決定もあります。ライブラリの言語は使い方そのものであり、ストリーミングのインターフェースはフレームワークに依存することがあり、組織がプラットフォームを指定することもあります。Draft はこれらを **Binding Decisions** として記録し、各行に拘束する理由と出どころ（人間の発言と日付か、その行を載せた報告への人間の承認）を添えます。

```markdown
## Binding Decisions
| Decision | Why it binds | Source |
|---|---|---|
| Next.js App Router | 回答が書かれるそばから届き、ルートごとの読み込み状態とエラー状態が体験の中核になる | 「Next.js で作りたい」「はい、App Router で」(2026-10-17) |
```

実装への道筋がすでに見えているときは、Draft はそれを **Direction** として記録し、段階、並列のレーン、人間が確認したい地点を書き並べます。Direction は見通しであって契約ではありません。**Acceptance Gates** には、作業の完了時に満たされているべきこと、すなわち通るべきコマンドと人間が与える承認を書きます。Acceptance Gates は作業が受け入れられた時点で退役します。

拘束するのは人間だけです。LLM は技術を提案できますが、その技術は人間が選ぶまで何も拘束しません。コードにすでにある技術は既存の前提であり、コマンドは報告でそれを示し、design.md には記録しません。それが Binding Decision になるのは人間が理由を述べたときだけです。

### Realize

**Intent:** 設計原則に基づいてコードを書く。

文書化された原則と Binding Decisions に従ってコードを実装します。Direction には従わない理由がない限り従い、外れるときはその旨を述べます。人間のゲートでは止まります。

### Reflect

**Intent:** 実装の結果に基づいてドキュメントを更新する。

実装から学んだことがあれば、ドキュメントを更新します。コードを Binding Decisions に照らし、終わった Direction は実際に起きたことに書き換えます。

指がキーボードの上を速く走りすぎてコードが設計を追い越すこともあります。ハーネス時代には、その指はエージェントのものであることが多くなりました。

---

Realize と Reflect はおおむね逆関数です。

-----

## 🤝 役割: 人間と LLM

DDL では人間と LLM は対等なパートナーです。

|       | 人間               | LLM                    |
|-------|--------------------|------------------------|
| 強み | 最初の直感、長期の視野、忍耐 | 技術知識、パターン認識、言語化 |
| 弱み | 網羅性、実装の詳細 | 短期バイアス |

人間がペースを制御し、LLM の短期バイアスを補正します。

エージェントが長く並列に走るようになると、人間の分担は具体的になります。すなわち、何を拘束するかを決め、どこを確認するかを決め、そのゲートで承認することです。エージェントはゲートのあいだで働きます。

-----

## 🌊 柔軟に

DDL は厳格な手順ではありません。

- 望むなら Draft を飛ばして Realize に直行しても構いません
- それでうまくいくなら、ドキュメントを書く前にコードを仕上げても構いません

作業が流れているときは、流れるに任せてください。

大事なのは作業のあとにドキュメントを更新すること（Reflect）です。

## ⚠️ アンチパターン

| パターン                      | 問題                          |
|------------------------------|----------------------------------|
| ドキュメントなしでコードを書く | 次のセッションが設計なしで始まる |
| プロセスに厳格に従う | DDL は厳格な手順ではない |
| LLM に全部やらせる | 人間の判断と長期の視点が欠ける |
| 人間が全部やる | LLM の言語化と技術知識が使われない |
| ツール化を目的にする | 意図が先で、ツールは手段 |
| DDL のドキュメントを永続させようとする | 不要になったら削除する |
| 形式に囚われる | DDL は一時的なメモ |
| エージェントにスタックを黙って選ばせる | 誰も合意していない決定がコードを拘束する |
| ハーネスの記憶を設計として扱う | エージェントは覚えているが、人間は合意していない |
| Direction を契約として扱う | 見通しが固まって誰も見直さない計画になる |
| 要約から承認する | コンパクション（会話の圧縮）を経た会話は報告ではない。人間は目の前にあるものを承認する |

-----

## 📋 まとめ

DDL は厳格な方法論ではなく、目的と設計の集まりです。

それは人間と LLM がセッション、エージェント、ハーネスをまたいで設計を共有し続けるための一時的なメモです。

最終的にはコードが正（source of truth）になります。DDL のドキュメントは不要になったら削除してください。

> **ツール支援の選択肢**: [Claude Code](../../claude-code/) (`/draft`, `/realize`, `/reflect` + サポートコマンド) | [OpenAI Codex](../../codex/) (`$draft`, `$realize`, `$reflect` + サポートスキル)
