# DDL Repository

## Protocol

→ DDL-PROTOCOL
→ Read the DDL protocol before executing any command, when it is not already in context, in the lookup order of protocol §2.5: this repository's source `claude-code/skills/ddl-protocol/SKILL.md` is the project's copy of the protocol, and `claude-code/skills/<name>/SKILL.md` the project's copy of each command, so a DDL command run here follows them; then the user-level copy `$HOME/.claude/skills/ddl-protocol/SKILL.md`

## Notebook

@../design.md

The line above imports `design.md` into this file, so the notebook is in context from session start and after a compaction (Claude Code adapter, protocol §2.5). A project with a root `CLAUDE.md` writes `@design.md`; a project whose notebook is another file (protocol §3) points the line at that file.

## Commands

| Command | Intent |
|---------|--------|
| `/draft` | Write the user-side experience first, with the decisions and outlook it depends on |
| `/realize` | Write code based on design principles and Binding Decisions |
| `/reflect` | Update documents based on implementation |
| `/validate` | Run mechanical validation per scope: the Validation block and the mechanical gates in Acceptance Gates |

## Structure

- `design.md` - Project design document (scopes, principles, validation; Experience, Binding Decisions, Direction, Acceptance Gates when drafted — protocol §3)
- `docs/en/design_philosophy.md` - English (canonical reference; `/resonate` refines both languages, and neither is a one-way source)
- `docs/en/design_philosophy_extended.md` - English extended
- `docs/ja/design_philosophy.md` - Japanese
- `docs/ja/design_philosophy_extended.md` - Japanese extended
- `README.md` - Public overview (shows `assets/main.webp`)
- `assets/` - The overview image: `main.webp` is what the README shows, and `main.png` is the original it was made from (kept as the source)
- `claude-code/` - The Claude Code source, in the layout of a project's `.claude/`:
  - `claude-code/skills/<name>/SKILL.md` - The single source of the 9 skills (the 8 commands and the protocol skill `ddl-protocol`)
  - `claude-code/CLAUDE.md`, `claude-code/settings.json`, `claude-code/agents/`, `claude-code/README.md` - The project template, the Claude Code adapter, and its README, hand-maintained
  - `claude-code/hooks/ddl_gate.py` - The gate, generated by `tools/sync_mirrors.py` from `tools/ddl_gate.py`; do not edit it by hand
- `codex/` - The Codex source, in the layout of a project's root:
  - `codex/AGENTS.md`, `codex/README.md`, `codex/.codex/` (except `hooks/ddl_gate.py`) - The project template, its README, and the Codex adapter, hand-maintained
  - `codex/.agents/skills/`, `codex/.codex/hooks/ddl_gate.py` - Generated by `tools/sync_mirrors.py` (the skills from `claude-code/skills/`, the gate from `tools/ddl_gate.py`); do not edit them by hand
- `bin/install.sh`, `bin/uninstall.sh`, `bin/doctor.sh` (wrappers around `bin/ddl_setup.py`) - The user-level install: the skills, agent definitions, gate, and rules are symlinked into `$HOME/.claude/` and `$HOME/.codex/`, and the hook wiring is merged into the user settings (`--project DIR` copies the per-project layout instead)
- `tools/sync_mirrors.py` - The generator (`--check` exits 1 when a generated file differs)
- `tools/ddl_gate.py`, `tools/test_ddl_gate.py`, `tools/fixtures/` - The gate hook (the source of every `hooks/ddl_gate.py`) and its tests (`python3 tools/test_ddl_gate.py`)
- `.claude/CLAUDE.md` - This file, the only file under `.claude/` (the adapter and the skills come from the user-level install)

## Detection Targets

Every command defines its own D-targets (D1, D2, …). Cross-cutting targets below apply globally.

+++DETECT:
  G1: Vague Intent — Task description lacks measurable outcome
  G2: Scope Creep — Change touches files outside stated scope
  G3: Principle Violation — Action contradicts design.md principles
  G4: Missing Validation — No verification step after mutation
  G5: Leaked Specifics — Project-specific paths/commands hardcoded in framework files
  G6: Silent Failure — Error swallowed without user notification
  G7: Unreviewed Mutation — Shared artifact changed without +++STOP

## Behavior

### On session start

1. This file is already in context: Claude Code loads `CLAUDE.md` or `.claude/CLAUDE.md` at session start and re-injects it after compaction. Do not read it again
2. `design.md` loads with this file through the adapter's import (protocol §2.5); when the import is unavailable, read `design.md` if it exists. Extract scopes, principles, validation commands, and the Experience, Binding Decisions, Direction, and Acceptance Gates when present. It stays in context; commands re-read it only when it is no longer in context after a compaction, and a worker reads only the sections its prompt names
3. The DDL protocol loads when a command runs (Phase 0, lookup order in protocol §2.5), not at session start
4. Automatic memory is a recall layer: a decision found only there is a proposal until design.md records it

### On any task

1. Identify which scopes (from `design.md`) are affected
2. Run the command's Phase sequence
3. Scan for Detection Targets at each phase boundary

### On completion

1. Summarize what changed (files, lines, scopes)
2. List any Detection Targets that fired
3. Suggest next command if applicable (`/draft` → `/realize` → `/reflect`)

## Constraints

+++NEVER: Hardcode paths or commands — scopes and validation come from design.md
+++NEVER: Auto-proceed past a +++STOP
+++NEVER: Spawn agents when a SWARM has fewer than 2 units (scopes, Direction lanes, files, document pairs, approved changes; protocol §2.3) — for 2+, follow +++SWARM semantics (mandatory when condition is true; only the lead fans out; runtime mapping in protocol §2.5)
+++NEVER: Add AI attribution to commits or generated code
